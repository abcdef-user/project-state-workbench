# AI 协作说明

AI 通过 MCP stdio 入口 `node server/src/mcp-server.js` 参与协作。用户需在当前对话中明确开启共享状态，AI 先调用 `project_open_session`，再读取 `project_get_surface` 的摘要。会话令牌仅存内存，调用 `project_close_session` 后失效；后续读写受令牌和任务作用域限制。`actorId` 是自报标签，不是可信身份认证。服务端无法自行核实用户是否真的同意，授权依赖宿主权限和协作纪律。

建议先读状态与版本，再写记录。能合并的写入优先使用 `project_apply_batch`，减少工具往返；任务创建、认领、释放和完成使用对应工具；文件观察、操作结果和决策分别用 `project_observe_artifact`、`project_record_operation`、`project_record_decision` 登记。写入版本号用于处理并发冲突。建议、待确认事项和已确认决策要分开，不要把模型的推测写成事实。记录应包含实际执行动作、验收证据、相关文件哈希和失败信息；只有覆盖每条验收条件后才标记完成。

工具返回成功不等于现实任务真的执行，SQLite 历史也不是防篡改审计。AI 应如实说明自己做过什么、没做什么，并请人核验关键结果。对于需要用户授权或外部环境操作的事项，应明确停点，不要用口头声明替代实际授权。共享状态中不要写入密钥、真实数据库、私密配置或无关个人资料。版本与测试状态以根 `RELEASE_CHECKS.md` 为准；0.1.0 包含内核 0.5.0 与工作台 1.3.2。测试通过不证明现实交付，也不构成法律或安全保证。

MCP 返回给宿主的状态可能进入模型提供商的上下文。插件本身不调用模型 API，并不等于宿主会将状态限制在本机；使用前应检查宿主和提供商的数据处理设置。
